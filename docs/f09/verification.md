# F-09 검증 기록

검증일: 2026-11-07 (한국 시간). Pleos Connect v2.1.0 / API 34 / Vehicle 2.3.2 / TTS 3.3.1. 로그 시각은 에뮬레이터의 기기 시각이다.

## 가상 터널·가상 차량 + 실제 TTS

[실행 로그](verification/fake-supported.log)

- 동일 진입을 두 번 주입했으나 `Place(tag=tunnel)`은 한 번 발행됐다.
- 기존 `s01_scene` 마지막 문장 → 질문 안내·대기 → `tunnel_flashback` 3문장 → `s02_driver` 순서로 진행했다.
- 가상 밝기 70→25, 송풍 2→3 변경 후 약 4초 뒤 70/2로 복원됐다.
- 터널 3문장 각각에서 TTS 재생 RMS가 0보다 큰 콜백과 완료 응답을 확인했다. 사람의 직접 청취 검증은 아니다.
- 자동 점검이 `SMOKE complete`로 완료됐다. 실제 조명·공조 변경 성공을 뜻하는 로그는 아니다.

## Pleos SDK 효과음 대체 경로

[공조 OFF 실행 로그](verification/sdk-fallback.log)

- 입력은 가상 터널이고 출력은 `PleosDirector`다.
- 초기 검사에서 송풍 구역 ID를 공조 전원 조회에 그대로 쓰면 실패했다. 각 속성의 capability 구역을 따로 조회하고 송풍 구역을 포함하는 전원/AUTO 구역을 찾아 읽도록 보완했다.
- 최종 실행에서는 공조 꺼짐을 확인했고, 전원을 켜지 않고 효과음 대체 경로로 진행했다. 터널 3문장과 다음 본편 전환이 정상 완료됐다.
- 이 실행은 대체 경로 검사다. 실제 변경/복원은 아래의 공조 ON 검사에서 별도로 확인했다.

## Pleos SDK 실제 값 변경·복원 성공

[SDK 조회 로그](verification/sdk-control-success.log), 기기 시각 11-06 23:59:32~46, PID 27453.

- 사용자가 Virtual Console에서 Power ON / AUTO OFF를 설정한 뒤 `CabinVerificationActivity`를 실행했다. 하드웨어가 에뮬레이터인지 확인하는 디버그 전용 화면이다.
- 시작값은 밝기 70, 송풍 3, 전원 true, AUTO false였다.
- 앱과 같은 `PleosDirector.perform(Effect.TUNNEL)` 경로를 호출하고 SDK로 값을 반복 조회했다. 가상 `FakeCabinPort` 값이 아니다.
- 호출 후 680ms 조회에서 밝기 23 / 송풍 4를 확인했고, 4,409ms 조회까지 유지됐다. 4,673ms 조회에서는 밝기 70 / 송풍 3으로 복원됐다. 조회 간격이 있으므로 정확한 변경 시각이나 지연 상한을 뜻하지 않는다.
- `CONTROL PASS` 및 `RESULT control=true originalSettingsRestored=true`를 확인했다. 테스트 준비에 사용하는 설정도 끝에 다시 조회했고 Power ON / AUTO OFF를 유지했다.
- 이전에는 전원 켜기 요청이 성공 응답을 반환해도 조회값이 false였고 송풍 쓰기는 사용 불가로 거절됐다. 사용자 콘솔 설정 후 위 경로가 성공했다. 성공 콜백만으로 실제 변경을 단정하지 않고 재조회해야 한다.
- 이 검사는 조명·송풍 제어 경로에 한정한다. 실차, 실제 GPS 터널 감지, 효과음의 사람 청취 검증을 의미하지 않는다.

## 지도 + Android GPS + 자동 장면 실행

[최종 GPS 실행 로그](verification/gps-auto-route.log), [입력 경로](verification/gps-route.json). 기기 시각 11-07 17:20~21, PID 32061.

- 지도 원본은 OpenStreetMap way 37930783 v33, 남산3호터널 도로 중심선이다. 원본 좌표를 보존하고 좌우 30m 판정 구역을 생성했다. 출처와 ODbL 표기는 앱 자산 및 README에 포함했다.
- `adb emu geo fix`로 터널 밖 → 안 → 밖 좌표를 입력했다. 앱은 Android GPS_PROVIDER에서 오차 약 5m의 위치를 받았다. 테스트 앱이 Place 이벤트를 직접 보내지 않았다.
- 17:20:48.646 진입 이벤트 1회 → 17:20:55.920 `tunnel_flashback` → 3문장 실제 TTS 완료 → 17:21:11.020 `s02_driver` 본편 복귀 → 17:21:12.707 이탈 이벤트 1회를 확인했다. 같은 내부 좌표가 계속 수신돼도 추가 진입은 없었다.
- 이번 GPS 실행의 SDK 조회에서는 공조 AUTO 상태여서 효과음 대체 경로를 사용했다. 조명·송풍 변경 성공은 위 별도 SDK 조회 검증 결과와 구분한다.
- 주행 상태는 테스트 전용 Driving을 사용했다. 메인 앱에서는 기존 실제 차량 입력과 GPS 이벤트를 병합했다. GPS 시연이 F-01 실차 주행 검증을 대신하지 않는다.
- 설치 직후 첫 실행에서 위치 구독이 시스템에서 해제되는 현상을 관찰했다. 패키지 갱신 처리가 끝난 뒤 재실행하여 정상적인 연속 수신을 확인했다. 재현 스크립트는 앱 설치와 별도로 실행한다.
- 검증 후 테스트 앱을 중지하고 에뮬레이터 좌표를 시험 전 기본 위치(37.421998, -122.084)로 되돌렸다.

## 한계와 환경 이슈

- 남산3호터널 한 구간의 실제 지도 데이터와 Android 위치 수신은 연결했다. 전국 구간 검색·경로 매칭·실차 위치 수신은 미검증이다.
- 장면 삽입은 현재 장면과 질문 대기 구간 다음이다. 터널이 짧아 재생 전에 이탈하면 장면이 취소된다.
- 프로세스 강제 종료·전원 차단·SDK 늦은 적용 상황에서의 원상 복구는 보장하지 않는다.
- 백그라운드 에뮬레이터의 시스템 재시작과 일반 실행 직후 오디오 포커스 거부가 있었다. 시스템 안정화 후 재실행한 최종 SDK 로그는 끝까지 완료됐다. 테스트 화면에 음성 오류 재시도와 자동 점검 시간 초과 안내를 추가했다.
